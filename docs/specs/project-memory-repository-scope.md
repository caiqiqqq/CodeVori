# 项目记忆的仓库范围与旧数据迁移

## 产品规则

- 本地 Git 仓库的主工作区及其 linked worktree 共用一份项目级记忆。范围由规范化后的 Git common directory 确定；不同 clone 即使远端 URL 相同，也不自动合并。
- 有 `workspaceIdentity` 的工作区继续按该身份隔离；非 Git 本地目录继续按绝对工作区路径隔离。工作区路径仍用于文件操作和展示。
- 设置页每份实际项目记忆只显示一项。仓库目录显示路径；身份隔离的目录同时显示路径、远程身份和短 ID；历史目录无法确定来源时显示短 ID，不能把相同 basename 当成同一项目。
- 项目级记忆只保存跨工作树长期有效的事实。仅对某个任务或工作树有效的内容不自动写入项目记忆。

## 所有者和事件顺序

`workspacePath / workspaceIdentity → 共享路径解析器 → 记忆根目录 → CLI 或 ACP 读写 → 设置页目录投影`

- 共享的 Node 路径解析器决定项目记忆身份。CLI 与 ACP 不分别实现 Git 工作树识别。
- 这个项目记忆范围只用于长期事实；任务路由、会话绑定和其他状态继续使用 `workspaceIdentity?.trim() || workspacePath`。
- 记忆文件及 `MEMORY.md` 是持久化事实；设置页目录是只读投影，不拥有第二份记忆状态。
- 迁移与 ACP 写入共用仓库记忆目录的文件锁，索引更新按获取锁的顺序串行执行。
- 解析器先检查 `workspaceIdentity`。本地路径通过 `.git` / `commondir` 找到 common directory；解析失败时保持旧的路径级身份，不猜测远端 URL。
- 在首次使用新根目录前，迁移当前工作区可验证的旧路径级目录。迁移对重复执行幂等；目标文件内容冲突时保留两份且不覆盖原件。

## 旧数据边界

- 现存 `zcode` 的四个旧目录先逐项核对，再合并为一份仓库记忆：两条 Git 提交偏好保留，三条委派规则合并为一条。完成校验后旧目录移出活跃列表，保留可恢复备份。
- 无法从哈希或现存路径证明仓库归属的目录不自动合并或删除。
- 自动迁移只处理当前可验证的工作区旧目录；已删除工作树的历史目录需要明确映射后迁移。

## 验收场景

1. 同一 Git common directory 的主工作区和两个工作树解析到同一记忆根目录；独立 clone、不同 `workspaceIdentity` 以及非 Git 目录仍各自隔离。
2. CLI 与 ACP 使用相同根目录；现有旧目录中的事实在迁移后可读取，新事实只写新根目录。
3. 重复迁移不重复生成索引或覆盖不同内容；冲突保留且可定位；旧目录在验证前始终可恢复。
4. 设置页不出现多个同名 `zcode`；不可识别的旧目录显示短 ID，并可与已归属仓库区分。
5. 桌面及手机 Web 通过相同服务契约读取列表；浅色、深色及窄屏下名称可读，菜单仍可操作。
