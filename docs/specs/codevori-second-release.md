# CodeVori 第二个安装版本

## 产品规则与交付范围

- 第二个本地安装版本为 `1.0.1`，仍以根 `package.json` 为唯一版本来源；构建元数据、应用信息与安装包保持一致。
- 提交并推送当前已完成的 CodeVori 构建修复、ACP 时间轴与附件历史、项目/任务混合分屏修复，目标为用户的 `private/main`。保留首版产物与历史构建记录，不提交安装包或编译生成的 sourcemap。
- 从推送成功的固定提交创建独立构建 worktree，重新编译桌面、内置 Agent 和 Computer Use 插件，交付 macOS arm64 的 DMG 与 ZIP。构建不覆盖开发进程的产物或真实用户数据。
- 复用首版的独立品牌、免登录启动、官方应用升级禁用和用户数据兼容规则，不新增产品状态或协议行为。安装包启动测试从根版本读取期望值，不固定为首版版本号。
- 构建仅生成本地安装包，不发布 GitHub Release。没有 Developer ID 和公证凭据时继续使用 ad-hoc 签名并如实记录公证状态。

## 所有者与顺序

```text
根版本与已验证源码
    → 提交 → 推送 private/main → 核对远端 commit
    → 独立 worktree 编译 → 打包与资源闭包校验
    → 临时用户目录启动 E2E → 归档 DMG / ZIP / 校验和 / 构建 commit
```

- 根 manifest 唯一拥有应用版本，现有 build metadata 负责关联提交与构建时间。
- 会话、附件、布局和导航状态继续由对应现有 owner 持有；打包操作不修改它们。
- 只有提交与远端一致且安装包验证成功后才能宣告交付；网络或构建失败必须分别记录。

## 验收

1. `private/main` 与本地提交一致，新增 spec、实现与测试完整入库，生成的 `schedulerProtocol.d.ts.map` 不入库。
2. 执行相关单测、类型检查、Lint 与架构检查；保留已有警告的真实数量。
3. 打包版显示 CodeVori `1.0.1`，全新临时用户目录启动免登录主窗口，官方更新状态禁用。
4. 最终 ASAR 运行时依赖闭包、平台原生资源、内置 Agent 和本次构建来源一致；签名完整性通过。
5. DMG 和 ZIP 完整性通过，产物记录版本、精确源码提交、大小与 SHA-256。
