# 对话标签与智能体图标

## 产品规则

- 顶部标签与当前可见工作台的对话面板一一对应，按布局叶子的显示顺序排列。单面板显示一个标签，分屏打开两个、三个或四个面板时显示相同数量的标签，不再只显示当前会话的标题。
- API 草稿面板显示本地化的新建任务标签，ACP 草稿显示所选智能体名称；会话创建后在原标签内更新标题和图标，不新增重复标签。关闭、删除或归档面板后，标签随现有布局同步消失；最后一个面板的关闭保护沿用现有规则。
- 标签标题、ACP Agent 和 API 模型取自该面板现有会话投影。ACP 复用 `AcpAgentIcon`；API/ZCode 复用 `TaskAgentIcon` 及其所属 Host 的供应商图标，不能用当前焦点会话的图标替代其他标签。
- 点击标签仅复用面板已有焦点处理，保留分屏、paneId、正文、输入草稿和会话连接，不创建、认证、恢复或重新读取会话。标签选中态与面板焦点双向一致。
- 长标题截断并可查看完整标题，标签数量多时仅标签栏横向滚动，页面无横向滚动条。保留原工作区上下文、会话更多菜单和右侧工具按钮；不重写对话页。
- 标签支持方向键、Home/End 和正确的选中态。普通 Web 与桌面使用同一实现；没有工作台标签容器的手机远控和其他独立 SessionPane 保持现有布局。

## 所有者与接口

`paneLayoutStore` 或活动 `workbenchGroupStore` 继续唯一拥有布局和焦点。V4WorkspaceChatArea 按已有 keyed leaves 渲染标签，复用同一个 `handleFocusRequest`；不新增打开会话列表或第二份 session 绑定。

WorkspaceHeader 只提供标签栏的 DOM 挂载位置，V4WorkspaceChatArea 持有每个标签的 DOM 挂载位置。SessionPane 将已有标题与图标直接投影到对应标签，不复制 Host 会话事实，不新增列表、readSession、ACP list/read 或模型调用。DOM 引用不持久化，不进入协议或服务。

```text
现有布局所有者 -> 可见 keyed leaves -> 顶部标签壳与 DOM 插槽
                                            ^
每个 SessionPane 的已有会话投影 -> 标题 / 对应智能体图标

点击标签 / 方向键 -> 原 handleFocusRequest -> 原布局所有者更新焦点
                                                    |
                                    标签选中态 / 面板焦点 / 原生导航
```

## 边界

- SessionPane 的绑定改变时，原生标题与模型只读取匹配 sessionId 的 snapshot，不能短暂显示上一条对话的标题或图标。
- ACP 打开请求仅在尚未消费时限制标题的会话身份；请求消费后，标题和图标跟随面板当前智能体与会话。用户切换其他 ACP 或切回 API 时，不能被旧打开请求或旧布局绑定固定在原智能体图标上。
- 同 ID 不同 native/ACP、同 ID 不同 workspaceIdentity 均以原 paneId 隔离。跨工作区标签仍读取自己的 Host 供应商配置。
- 不改布局持久化 schema、Host owner/lease、Desktop continuous 或手机 Web replayable 链路；刷新按既有布局恢复并重新投影标签。

## 验收

1. API、Codex ACP、Claude ACP 与草稿同时打开时，标签数量与面板数量一致，标题和智能体图标各自正确。
2. 点击或键盘选择标签与点击面板的焦点相同；存活面板零重挂载，输入内容保留，点击 ACP 标签不走原生选择命令。
3. 关闭主面板和 secondary、仅剩一个面板、归档、刷新与新建任务时，标签数量及选择态准确，无幽灵标签或旧标题。
4. 宽屏/窄屏、浅色/深色和中英界面可用，长标题不挤压右侧工具按钮；图标素材实际渲染，页面没有横向溢出。
5. 浏览器 E2E 使用真实标签、焦点、布局及图标组件，模型/Host 边界使用合成替身；实际运行现有分屏关闭回归、类型检查、Lint 和架构检查。
